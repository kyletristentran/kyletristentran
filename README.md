## Kyle Tran

CRE analyst working in ARGUS, Python and agentic AI

I work in real estate finance and build the tooling around it. I hold a B.S. in Real Estate Development from USC (August 2026), and in summer 2026 I built AI and automation systems for an industrial REIT. I am available now for full-time CRE analyst roles.

Commercial real estate runs on documents and spreadsheets that are hard to audit. A memo stops matching its model as soon as either one changes. An offering memorandum spreads about ten figures across forty pages of photography. A rent roll gets passed around as a screenshot. The projects below tie each figure to the cell, page or source it came from, and they report a failure when the source cannot be read.

### Selected work

| Project | Description |
|---|---|
| [om-extract](https://github.com/kyletristentran/om-extract) | Extracts structured rent rolls from CRE offering memorandums. It runs on a local model, so it needs no API key and uploads nothing. Each record carries a confidence rating, and anything the pipeline cannot read goes to a review queue. |
| [kt-portfolio-dash](https://github.com/kyletristentran/kt-portfolio-dash) | A real estate portfolio dashboard built with Next.js and Supabase. It uses row-level security and a public demo tenant enforced by the database. |
| [real-estate-tech](https://github.com/kyletristentran/real-estate-tech) | Power Platform prototypes: an Excel task-pane add-in, Office Scripts, a canonical pro-forma schema and Power Automate flows for budget approval. |
| [kt-claude-plugins](https://github.com/kyletristentran/kt-claude-plugins) | A Claude plugin marketplace. Its `kt-cre` plugin converts a spreadsheet into a committee memo in which every figure carries an A1 cell reference, with a verifier that reopens the workbook and fails the build when a number no longer matches. It also applies one visual standard to PDF, Word, Excel, PowerPoint, HTML and email. The other plugins cover token cost and interface design. |
